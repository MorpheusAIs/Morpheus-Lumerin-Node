`models-config.json` tells the proxy-router how to translate on-chain `modelId` values into actual backend HTTP calls. The schema is enforced by [`proxy-router/internal/config/models-config-schema.json`](https://github.com/MorpheusAIs/Morpheus-Lumerin-Node/blob/main/proxy-router/internal/config/models-config-schema.json).

## Per-model fields

| Field | Required | Notes |
|-------|----------|-------|
| `modelId` | yes | The on-chain model id (32-byte hex) |
| `modelName` | yes | Human-readable name |
| `apiType` | yes | One of `openai`, `claudeai`, `prodia-sd`, `prodia-sdxl`, `prodia-v2`, `hyperbolic-sd`, etc. |
| `apiUrl` | yes | Full backend URL including the endpoint path |
| `apiKey` | optional | Backend API key (resale providers usually need this) |
| `concurrentSlots` | optional | Distinct concurrent chats your backend can handle for **this** model |
| `capacityPolicy` | optional | `idle_timeout` or `simple` |

<Note>
**`concurrentSlots` is per-model, not global.** The proxy-router will accept up to `sum(concurrentSlots)` across all configured models concurrently. There is no built-in global cap. If your hardware can serve only one of N models at a time, configure all N in `models-config.json` but **only post a bid for the one currently active**, and rotate the bid when you want to switch. Prefer bidding on existing marketplace `modelId`s rather than minting duplicates — see [Register on chain](/providers/full/register-onchain). See also [Pausing or temporarily disabling a model offering](/providers/full/register-onchain#pausing-or-temporarily-disabling-a-model-offering).
</Note>
| `parameters` | optional | Per-`apiType` extra parameters (e.g. SD `cfg_scale`, `steps`) |

For the canonical per-`apiType` schema, see the JSON schema file linked above.

## Reload without a restart

The file is read once at boot. Historically, adding or editing a model meant restarting the proxy-router, which cuts every open session — and each cut session can be closed out as a dispute against your success ratio. Since the release after v7.11 you can re-read the file in place:

```bash
curl -s -X POST -u 'admin:yourpassword' http://localhost:8082/config/models/reload
# {"added":["0x…"],"removed":[],"healthSweepQueued":true}
```

- Permission `system_config` (the admin user's `*` whitelist covers it).
- The file is parsed into a fresh table and swapped atomically. Requests already in flight keep the config they started with; the next request sees the new table. A new model is servable as soon as the call returns.
- **A file that fails to parse or validate returns `400` and leaves the running table untouched.** A half-edited file cannot empty a serving node. The error body names the problem: `{"error":"models config not reloaded, previous table still in force: …"}`.
- `added` / `removed` list the model IDs that changed relative to the previous table, sorted. An unchanged file returns both empty.
- `healthSweepQueued` is `true` when a [model health](/providers/full/model-health) sweep was queued so models with an active bid are probed now (same as `POST /healthcheck/models/refresh`). Models without a bid cost nothing until one is posted. A `tee`-tagged model added this way is attested during that sweep; with `MODEL_HEALTH_CHECK_DISABLED=true` it will not be attested until the next restart.
- Applies to `MODELS_CONFIG_PATH` on disk. With `MODELS_CONFIG_CONTENT` the content was written to the path at first boot; edit the file at that path and reload, or change the env and restart.

On older releases the endpoint returns `404` — restart the proxy-router instead. Removing a model that has open sessions makes those sessions fail at the receiver; drop the bid first and let sessions drain.

## Inline content (for TEE / Akash)

For deployments where mounting a JSON file is impractical, set `MODELS_CONFIG_CONTENT` to a **single-line JSON string** with the exact same shape as above. The proxy-router reads it instead of `MODELS_CONFIG_PATH`. This is the standard approach in [TEE](/providers/full/secretvm-quickstart) and [Akash](/providers/full/proxy-router-akash) deployments.
