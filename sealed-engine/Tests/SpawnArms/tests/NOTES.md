# tests/ — arm → spec-test map (harness; other agents add the refusal arms)

Format: each arm names the SPEC-R1-R3.md test it gates and the sentence it
checks, plus its control (TASK-tests.md: every refusal arm needs a positive
control in the same run, so a harness that refuses everything cannot pass).
Every arm runs with its own 60 s timeout and prints PASS / FAIL / SKIP with a
reason; `make test` exits nonzero if any arm FAILs. Every SKIP is labeled
with its true reason (FIXES-2 6: not "needs root" — the real blockers are
things like a test-build engine or an unusable reqgen), and those arms are
listed here as well.

Notes from the arms-r3 run (the test Mac, 2026-09-30):
- The module requires requirement bytes: a spec with `requirement == NULL` is refused `SEALED_SPAWN_REQUIREMENT`. The "launch requirement off" configuration of R3-T1's engine-only arms is therefore expressed by attaching reqgen-generated bytes naming the spawned child's OWN CD hash (the kernel admits that child, so only the engine's check can refuse). The bytes are generated at run time by the Makefile's `reqgen` (a13.swift dumpfile route; it exits before launching anything).
- R1-T5 parts not expressible here (no root, and outside this module's contract): the static-initializer fault child and code-signing kill during load (need test-build children and the no-report checks over both DiagnosticReports folders), the restarted second-generation child, the handler-rights-deallocation oracle, and the report-writing control (needs a spawn without the spawn attribute).
- Status words observed: accepted child-ok suspended/running 0x22011311; child-gta suspended 0x22011315 (CS_GET_TASK_ALLOW set) — recorded for R3-T1's phase table.
