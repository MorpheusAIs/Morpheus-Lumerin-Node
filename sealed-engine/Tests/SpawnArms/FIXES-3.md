# Batch 3: arms that kill two surviving mutants (orchestrator mutation test, 2026-10-01)

Two deliberately broken copies of the fixed module are in mutants/. With either one in place of impl/src/sealed_spawn.c, the whole suite still passed on the test Mac (16 PASS, 2 SKIP, 0 FAIL). A gate that cannot see these regressions does not guard them.

1. mutants/mut-a-notify-before-insert.c requests the no-senders notification before inserting the send right (the order that was measured to deliver the notification immediately). It survives because every test child crashes within milliseconds, inside the reader's 2 s drain window. Add a child (tests/children/r2_latecrash.c) that waits about 3 s after it starts, then crashes, without ever connecting; set the arm's rendezvous deadline to 8000 ms. Arm r1_t5_late_crash: assert SEALED_SPAWN_DIED within about 1 s of the crash (report ms from spawn), reaped, exception_seen set. Expected: FAIL against mutant A (the reader has already exited, so the crash is not answered and the module waits for the deadline), PASS against the fixed module.
2. mutants/mut-b-no-sigreset.c drops POSIX_SPAWN_SETSIGDEF and POSIX_SPAWN_SETSIGMASK. It survives because the test parent's own signal state is all default. In tests/arms/r2_t1_inheritance.c, before spawning, make the parent's state non-default: set SIGPIPE and SIGUSR2 to SIG_IGN and block SIGUSR1 (restore after). The child's report must still show every signal at default and an empty mask. Expected: FAIL against mutant B, PASS against the fixed module.

Proof required for each: run the suite with the mutant copied over impl/src/sealed_spawn.c in a scratch copy of this folder (SLOT=mut-a3 / mut-b3), show the new arm FAILs, then run against the real module (SLOT=fix) and show it PASSes. Never leave a mutant in impl/src/. Record both results in tests/NOTES.md.
